# 界面可读性与自适应布局 TODO

本文用于分阶段改善 Flowlet 在不同屏幕、系统缩放和移动设备上的文字可读性、视觉舒适度与布局适应能力。

状态约定沿用 [`todo.md`](./todo.md)：

```text
[ ] 未开始
[-] 处理中
[*] 已实现，等待人工验收
[x] 已实现并通过人工验收
```

## 一、目标与边界

### 目标

- [ ] 桌面端在 Windows 100%–200% 系统缩放下保持清晰、舒适、可操作。
- [ ] 首次启动窗口根据当前显示器的有效工作区选择合理尺寸，不再把 `1200×720` 同时作为固定初始尺寸和最小尺寸。
- [ ] 保留 `1200×720` 作为概览页的重要验收基准，并继续满足该尺寸下无页面级滚动条的要求。
- [ ] 移动端正文、说明文字和交互控件达到平台常见可读尺度，并支持系统字体缩放或等效的应用内缩放能力。
- [ ] 普通文本达到 WCAG 2.2 AA 的 `4.5:1` 最低对比度；大文本和非文本控件按对应标准验收。
- [ ] 用户可按需要调整界面缩放或密度，偏好能够持久化。

### 非目标

- [ ] 不更换 Semi Design，不重新引入 Mantine。
- [ ] 不借可读性改造改变概览页模块划分、功能边界或左侧菜单枚举。
- [ ] 不按具体电脑型号维护样式分支。
- [ ] 不按物理分辨率直接放大或缩小字体。
- [ ] 不用页面级 `.semi-*` 覆盖、持续提高选择器优先级或 `!important` 修补全局问题。

## 二、已确认的现状

- [ ] 将以下现状记录为改造前基线截图和测试数据：
  - 全局正文 `13px`、强调正文 `14px`、说明文字 `12px`、图表标签 `11px`。
  - 主窗口与项目详情窗口的初始尺寸和最小尺寸均为 `1200×720`。
  - 当前窗口恢复兜底只修正位置，不会在显示器工作区变小时缩小窗口。
  - 移动端 viewport 使用 `maximum-scale=1, user-scalable=no`。
  - 当前三级文字色 `#9199a7` 在常见浅色表面上的对比度约为 `2.55:1–2.87:1`。
  - 当前有大量 `9px–13px` 的页面级硬编码字号，桌面与移动端均受影响。
- [ ] 为桌面端和移动端各选取至少 3 个高频页面作为基线样本：
  - 桌面：概览、请求日志、会话管理。
  - 移动：概览、会话列表、会话详情。
- [ ] 记录 Windows 任务管理器、VS Code、AppFlowy 的同屏对照截图，只用于可读性和密度参考，不复制其产品结构。

## 三、阶段 1：建立统一排版与颜色 Token

### 1.1 排版体系

- [*] 在 `src/styles/tokens.css` 中建立语义化排版 Token，至少包含：
  - 正文：桌面默认 `14px / 20px`。
  - 正文强调：`14px / 20px`，使用 semibold 字重。
  - 说明文字：`12px / 16px`。
  - 小标题：`16px / 22px`。
  - 页面标题：`20px / 28px`。
  - 数据和代码等宽文字的字号与行高。
- [*] Windows 字体栈优先使用 `Segoe UI Variable Text` / `Segoe UI Variable`，中文优先使用 `Microsoft YaHei UI`，保留跨平台系统字体回退。
- [*] 将 Semi Design 的相关主题变量映射到 Flowlet 语义 Token，优先通过 Semi props、主题变量和共享组件控制字号与密度。
- [*] 明确 `11px` 仅允许用于非关键图表刻度等极少数场景；普通业务文字不得使用 `9px` 或 `10px`。
- [*] 将高频页面中的硬编码字号分批迁移到语义 Token，不做无审查的全仓机械替换。

### 1.2 颜色体系

- [*] 为浅色和深色主题分别建立正文、次要文字、三级文字、禁用文字的对比度清单。
- [*] 调整浅色主题三级文字，使普通文本在实际背景上达到至少 `4.5:1`。
- [*] 调整深色主题三级文字；当前 `#7e8a9c` 在 `#202a3a` 上约为 `4.13:1`，不足时继续提升。
- [*] 降低大面积纯白、蓝色辉光和高亮表面的刺激感，同时保持文字对比度；不得用“把文字变淡”制造柔和感。
- [ ] 检查成功、警告、错误、链接、禁用状态是否仅靠颜色传达含义。

### 阶段 1 验收

- [*] 概览、请求日志、会话管理三个桌面页面不再出现关键 `9px–11px` 文字。
- [*] 关键正文和说明文字具有明确、统一的行高。
- [*] 浅色和深色主题的普通文本对比度均达到 WCAG 2.2 AA。
- [*] `1200×720` 下概览页仍无页面级滚动条。

## 四、阶段 2：桌面窗口尺寸与 DPI 策略

### 2.1 统一窗口尺寸策略

- [ ] 抽出主窗口和项目详情窗口共用的窗口尺寸计算函数，消除两处独立的 `1200×720` 硬编码。
- [ ] 使用显示器工作区和 `scale_factor` 计算逻辑尺寸，不直接使用物理分辨率。
- [ ] 评估并用实机验证以下首次启动候选规则：

```text
logical_work_area = physical_work_area / scale_factor
initial_width  = clamp(logical_width  × 0.78, 1024, 1440)
initial_height = clamp(logical_height × 0.82, 640, 900)
min_width      = 1008
min_height     = 640
```

- [ ] 历史窗口状态合法时继续尊重用户上次尺寸、位置和最大化状态。
- [ ] 历史窗口大于当前显示器工作区时，同时修正尺寸和位置，确保窗口完整可见。
- [ ] 首次启动窗口居中；多显示器环境优先使用目标显示器工作区。
- [ ] 窗口从一个 DPI 显示器移动到另一个 DPI 显示器时，不重复执行应用级缩放，不突然改变用户手动设置的窗口尺寸。

### 2.2 窗口生命周期回归

- [ ] 验证隐藏到托盘再恢复时窗口尺寸和位置不丢失。
- [ ] 验证退出 Flowlet 后窗口状态正常保存。
- [ ] 验证最大化、还原、最小化和无系统边框窗口控制按钮。
- [ ] 验证主显示器断开、远程桌面、睡眠唤醒和显示器缩放变化后的恢复行为。
- [ ] 验证项目详情独立窗口与主窗口使用同一策略，但各自保存状态。

### 阶段 2 验收

- [ ] 1366×768、1920×1080、2560×1440、3840×2160 显示器均可首次启动并完整显示。
- [ ] Windows 100%、125%、150%、175%、200% 缩放下窗口不会超出工作区。
- [ ] 用户调整后的窗口状态不会被每次启动重新计算覆盖。

## 五、阶段 3：桌面响应式布局

- [ ] 按应用窗口的逻辑宽度建立统一断点，不按设备型号判断：
  - 小型桌面窗口：小于 `1008px`。
  - 标准桌面窗口：`1008px–1439px`。
  - 宽桌面窗口：`1440px` 及以上。
- [ ] 逐页检查固定宽度、固定高度、绝对定位和 `white-space: nowrap` 导致的截断。
- [ ] 小窗口优先重排、换行、折叠次要信息或使用组件内部滚动，不通过缩小字号塞入内容。
- [ ] 宽窗口限制长文本行宽，避免内容无上限横向拉伸；数据表格和矩阵可以利用额外空间。
- [ ] 检查 SideSheet、Modal、Tooltip、Toast 在各断点下的宽度和共享层级。
- [ ] 检查概览页既定 2×2 信息架构在 `1200×720` 下保持不变。

### 阶段 3 验收

- [ ] `1008×640` 下所有主要功能可访问，无不可恢复的内容裁切。
- [ ] `1200×720` 下概览页满足现有产品约束。
- [ ] `1440×900` 及更宽窗口不会出现过长文本行、空洞布局或无意义拉伸。

## 六、阶段 4：用户界面缩放与密度

- [ ] 在设置 → 通用设置 → 外观中增加“界面缩放”：`90% / 100% / 110% / 125%`。
- [ ] 增加“界面密度”：`舒适 / 标准 / 紧凑`；默认使用“标准”。
- [ ] 缩放和密度偏好在当前设备本地持久化，不写入 `config.json`，不参与渠道或代理热更新。
- [ ] 支持 `Ctrl + +`、`Ctrl + -`、`Ctrl + 0`，并避免与输入框、终端和 WebView 内容快捷键冲突。
- [ ] 缩放通过根级语义 Token 生效，禁止使用 `transform: scale()`；谨慎评估 CSS `zoom` 对断点、弹层和命中区域的影响。
- [ ] 密度只调整间距、行高、控件高度和列表行高，不把关键正文降到可读下限以下。
- [ ] 在界面上提供恢复默认值入口。

### 阶段 4 验收

- [ ] 125% 界面缩放下主要功能无文字截断或按钮不可点击。
- [ ] 90% 缩放仍满足最低字号和对比度要求。
- [ ] 修改设置立即生效，重启后保持；恢复默认值后完全回到标准状态。

## 七、阶段 5：移动端字体与自适应布局

- [ ] 移除移动端 `maximum-scale=1, user-scalable=no`，保留 `width=device-width`、安全区和必要的 viewport 配置。
- [ ] 建立移动端语义排版 Token：正文建议从 `15px–16px` 起，关键说明文字不得低于 `12px`。
- [ ] 检查 Android WebView 和 iOS WebView 是否实际跟随系统字体缩放；若未跟随，增加原生字体缩放读取或应用内等效设置。
- [ ] 在系统字体 100%、130%、150%、200% 下验证页面重排。
- [ ] 按当前应用窗口宽度适配紧凑、平板和大屏，不用 User-Agent 或 `isTablet` 决定布局。
- [ ] 检查底部导航、会话列表、详情 SideSheet、远程确认和表单的触控目标尺寸。
- [ ] 文字放大后允许合理增高和换行，不使用省略号隐藏关键状态或错误。
- [ ] 验证横屏、分屏、折叠屏和软键盘弹出后的可用高度。

### 阶段 5 验收

- [ ] 360×800、390×844、600×960、840×1080 视口下核心流程可用。
- [ ] 200% 字体缩放下不丢失关键内容或操作。
- [ ] 用户可以使用系统辅助缩放或应用提供的等效能力。

## 八、阶段 6：系统外观与可访问性

- [ ] 保持明暗主题跟随系统，并验证系统主题切换时 Semi Design 组件同步更新。
- [ ] 支持或兼容 `prefers-contrast: more`。
- [ ] 检查 Windows `forced-colors: active`，阴影消失后仍能识别卡片、按钮、焦点和选中状态。
- [ ] 保持清晰的 `:focus-visible`，不得只依赖背景色表示焦点。
- [ ] 支持 `prefers-reduced-motion`，避免非必要动画加剧疲劳。
- [ ] 确保文本放大到 200% 时核心内容和功能不丢失。
